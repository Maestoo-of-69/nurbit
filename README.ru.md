# Nurbit — «медсестра на орбите»

[English](README.md) · **Русский**

Nurbit — бета-версия настольного приложения для повседневного контроля здоровья
астронавтов (NASA Space Apps Challenge). Вместо длинных анкет — ежедневный
опрос на минуту; уточняющие вопросы — только когда этого требуют ответы. Каждый
сравнивается со **своей** историей. Приложение следит за пятью рисками NASA
Human Research Program, работает **без связи** и отправляет записи врачам на
Земле, когда связь появляется.

> **Учебный прототип.** Не медицинское изделие, не прошёл клиническую проверку,
> не сертифицирован. Все данные **синтетические**. Программа не ставит диагнозы,
> не назначает лечение и не признаёт никого непригодным к работе.

## Как скачать и запустить (Windows)

**Вариант А — просто пользоваться (инструменты разработчика не нужны).**
1. Откройте **[Releases → Nurbit 0.1.0 beta](https://github.com/Maestoo-of-69/nurbit/releases/latest)**
   и скачайте `Nurbit_0.1.0_x64-setup.exe`.
2. Запустите двойным кликом. Если Windows предупредит о неизвестном приложении
   (у него нет цифровой подписи), нажмите **Подробнее → Выполнить в любом случае**.
   Установка только для вашего пользователя, без прав администратора.
3. Откройте **Nurbit** из меню «Пуск» или ярлыка на рабочем столе и выберите профиль.

Обновление — установить новый релиз поверх старого. Удаление — *Параметры → Приложения → Nurbit → Удалить*.

**Вариант Б — скачать исходники и запустить.**
1. **Установить инструменты (один раз):**
   - Git — https://git-scm.com/download/win
   - Visual Studio Build Tools с набором «Разработка классических приложений на C++» — https://visualstudio.microsoft.com/visual-cpp-build-tools/
   - Rust через rustup (выбрать MSVC) — https://rustup.rs
   - Node.js 24 LTS — https://nodejs.org
2. **Скачать исходники:**
   ```bash
   gh auth login                                   # или ваши учётные данные Git
   git clone https://github.com/Maestoo-of-69/nurbit.git
   cd nurbit
   ```
3. **Проверить сборку:** `cargo test --workspace` (первая сборка — несколько минут).
4. **Установить зависимости интерфейса (один раз):** `cd apps/desktop`, затем `npm install`.
5. **Запустить приложение:** `npm run tauri dev` (в папке `apps/desktop`). Откроется окно Nurbit — выберите профиль.
6. **Собрать свой установщик (по желанию):** `npm run tauri build` → `target/release/bundle/nsis/Nurbit_0.1.0_x64-setup.exe`.
7. **Запустить сервер синхронизации (по желанию, второй терминал, корень репозитория):**
   ```bash
   $env:NURBIT_SYNC_TOKEN = "<ваш секрет, 16+ символов>"
   cargo run -p nurbit-server
   ```
   В приложении откройте **Sync**, введите `http://127.0.0.1:8787` и тот же токен → **Save settings** → **Sync now**.

**Если что-то не работает:** «Политика управления приложениями заблокировала
этот файл» — это Smart App Control блокирует свежесобранные программы (см.
[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) §9); ошибка о несовпадении версий
Tauri — выполните `npm install` и `cargo update -p tauri`.

## 1. Быстрый старт
**Установка (Windows 10/11):** запустите `Nurbit_0.1.0_x64-setup.exe` (≈4 МБ,
собирается в `target/release/bundle/nsis/`). Ставится только для текущего
пользователя в `%LOCALAPPDATA%\Nurbit`, без прав администратора; появляются
ярлыки в «Пуске» и на рабочем столе и запись для удаления в «Параметры →
Приложения». Маленький размер — потому что Tauri использует встроенный в
Windows WebView2. Установщик не подписан: на других ПК Windows может предупредить.

**Из исходников** (Rust 1.97+ MSVC, Node 24, WebView2):
```bash
cargo test --workspace
cd apps/desktop && npm install
cd apps/desktop && npm run tauri dev       # запуск в своём окне
cd apps/desktop && npm run tauri build     # релиз + установщик
```
**Чистые демо-данные:** закройте приложение и удалите
`%APPDATA%\com.nurbit.desktop\nurbit.db` — экипаж создастся заново.

## 2. Пользователи и профили
При запуске выберите, **кто пользуется приложением**; **Switch** слева внизу меняет пользователя.

| Профиль | Роль | Сюжет в демо |
|---------|------|--------------|
| Vega, Orion, Lyra, Atlas | Астронавты | Vega — ровные дни; Orion — сон ухудшается; Lyra — настроение ниже; Atlas — пропуски тренировок |
| Dr. Sirius | Врач на Земле | обзор экипажа, заметки, решения |
| Dr. Rigel | Второй врач | подтверждает или отклоняет отстранение |

**Зачем:** у ролей разные меню и действия; права ещё раз проверяются в Rust при
каждом действии. Пароля в бете нет (профили синтетические).

## 3. Функции для астронавта
**Overview (главный).** Статус сегодняшнего опроса, общий статус мониторинга,
очередь отправки, уровень каждого модуля, вход в ассистента. *Зачем:* одним
взглядом понять, всё ли в порядке.

**Daily check — 3 вопроса** (шкала 0–10, везде 10 = лучше): насколько отдохнули;
как тело (боль, симптомы); настроение и энергия. *Как:* нажать числа →
**Continue**. *Зачем:* опрос на минуту; ответы питают модули сна, поведения,
костей и SANS.

**Уточняющие вопросы.** Открываются при оценке ≤ 3 или падении на 3+ балла
от своего среднего за 7 опросов. Сон: часы, прерывания, бодрость. Тело:
**вопрос безопасности** (боль в груди, обморок, потеря зрения, сильная
головная боль, затруднённое дыхание), где проблема, падение/удар, зрение.
Настроение: стресс, концентрация, «связаться ли врачу?». Каждый блок
показывает *Why*. *Зачем:* не спрашивать лишнего, но не пропустить важное;
вопрос безопасности обязателен. Пороги — допущения прототипа.

**Итог и флаги.** Время, число вопросов и уточнений. Срочный симптом →
красный баннер «свяжитесь с медиком»; просьба связаться, изменение зрения,
падение → записываются для врачей. Обычные дни уведомлений не создают.

**History.** Графики с серой полосой **личной нормы** (своё среднее ± 2);
статусы: в норме / разовое отклонение / устойчивое изменение / мало данных;
закономерности «сон ↔ настроение», «сон ↔ тело» с пометкой «наблюдаемая
корреляция, не причина»; таблица опросов. *Зачем:* своя история говорит
больше общей нормы; норма **не меняется сама** — только врачом.

**Risk modules.** Пять рисков: кости (падения, боль, минуты тренировок;
плотность кости в полёте не измеряется), SANS (жалобы на зрение; не заменяет
осмотр), поведение (настроение, просьбы связаться; не диагноз), сон (оценки,
часы сна), радиация (доза против лимита NASA **600 мЗв**; рак не
обнаруживает). На вкладке — автоматическая оценка (*нет данных / нечего
сообщить / внимание / просмотр врачом*) с основаниями и недостающими данными,
затем таблица показателей с типом и доступностью в полёте. Подробно:
[docs/FEASIBILITY.md](docs/FEASIBILITY.md).

**Assistant.** Опишите симптом, по желанию — часть тела, тяжесть (0 = нет,
10 = хуже некуда), начало → **Search verified sources**. Ответ — до 3 карточек
источников (организация, документ, дата, раздел, почему показан). Тревожные
слова или тяжесть ≥ 8 → срочный баннер; вопросы о лекарствах → отказ; нет
совпадений → «No reliable source found». Активен только поиск по проверенным
источникам (офлайн, без языковой модели); локальная модель и облако показаны
как недоступные; голосовой ввод выключен (браузер отправляет звук в сеть).
*Зачем:* безопасный ассистент, который только пересказывает 14 проверенных
источников из [docs/REFERENCES.md](docs/REFERENCES.md); вопросы видят врачи.

**Sync.** Адрес сервера и токен → **Save settings** → **Sync now**; счётчики
«ждут / отправлены / конфликты», повтор каждые 30 с, индикатор в боковой
панели. *Зачем:* без связи записи копятся локально и доставляются один раз,
когда связь появится.

## 4. Функции для врача
**Crew.** Все астронавты, самые важные сверху: статус, последний опрос, что
требует внимания (включая тревожные симптомы), решения на проверке.

**Карта астронавта.** *Summary:* баннер безопасности, автоматическая оценка
(подписана «не диагноз»), тренды; при устойчивом изменении — **пересмотр
нормы** (утвердить новую с этого момента / оставить; причина обязательна);
вопросы ассистенту. *Check-ins:* все ответы и причины уточнений; **Add
annotation** — исправление с причиной, оригинал не меняется. *Notes &
decisions* (синяя рамка): обследование, допуск, **отстранение (нужен 2-й
врач)**, другое; заметки. *Зачем:* врач главнее программы, его решения
хранятся отдельно и ничего не перезаписывают.

**Pending reviews.** Отстранение ждёт второго врача: он может **Confirm /
Reject**, автор — нет (проверяется и в Rust). *Зачем:* такое решение не должно
зависеть от одного человека или программы.

## 5. Сервер синхронизации
```bash
$env:NURBIT_SYNC_TOKEN = "<ваш секрет, 16+ символов>"
cargo run -p nurbit-server        # http://127.0.0.1:8787
```
Переменные: `NURBIT_SYNC_TOKEN` (обязателен), `NURBIT_SERVER_DB`,
`NURBIT_SERVER_ADDR`. Адреса: `GET /health`, `POST /api/v1/sync/push`,
`GET /api/v1/crew`, `GET /api/v1/crew/{id}/checkins`. У каждой записи id и
SHA-256 отпечаток; ответы: **accepted**, **duplicate** (безопасный повтор),
**conflict** (обе версии хранятся), **invalid**. Нужен заголовок
`Authorization: Bearer <токен>`. HTTP — только для локального демо, в работе нужен HTTPS.

## 6. Защита данных
Медицинские записи только добавляются (триггеры SQLite запрещают изменение и
удаление); сохранение — одной транзакцией; выводы программы и решения людей
разделены; у каждого значения есть источник и время; у порогов — основание;
секретов в репозитории нет.

## 7. Архитектура
`crates/shared` — типы и протокол; `crates/medical-core` — чистая медицинская
логика; `crates/local-store` — SQLite десктопа; `apps/desktop` — Tauri
(React-интерфейс + команды Rust); `apps/server` — Axum; `knowledge-base` —
источники ассистента; `docs` — документы. Подробнее: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

### Технологии — что использовано и почему

**Основной язык — Rust (1.97, MSVC).** Вся медицинская логика, хранение,
синхронизация и сервер. *Почему:* безопасная работа с памятью без сборщика
мусора, скорость и строгие типы, которые ловят ошибки в полях медицинских
записей ещё при компиляции. Один язык для ядра приложения и сервера.
*Альтернатива:* Node/TypeScript (первый план) — проще начать, но больше ошибок во время работы.

**Оболочка десктопа — Tauri 2 (2.12).** Окно, установщик, мост Rust ↔ интерфейс.
*Почему:* настоящее устанавливаемое приложение, а не сайт; установщик ~4 МБ,
потому что используется встроенный в Windows WebView2; Rust-бэкенд «из
коробки»; белый список разрешений (интерфейсу доступно только `core:default`,
без файлов, shell и сети). *Альтернатива:* Electron — тащит целый браузер (100+ МБ).

**Фронтенд — React 19 + TypeScript 5.9.** Экраны, формы, навигация.
*Почему:* самая распространённая UI-библиотека; типы TypeScript повторяют
структуры Rust, ошибки видны до запуска. Навигация — обычное состояние React
(в десктопе нет адресной строки), отдельный роутер не нужен.
**Медицинских правил в TypeScript нет.**

**Сборка фронтенда — Vite 7** (с `@rollup/wasm-node`). Dev-сервер с горячей
перезагрузкой и сборка статических файлов, которые встраиваются в `.exe`.
*Почему:* быстро и просто. WebAssembly-версия Rollup — потому что Smart App
Control на компьютере разработки заблокировал его неподписанный нативный модуль.

**Стили — обычный CSS с дизайн-токенами** (`tokens.css`). *Почему:* все цвета,
размеры и анимации в одном месте; для небольшого приложения CSS-фреймворк не
нужен; цвета несут смысл (норма / внимание / тревога / врач) и всегда с текстом.

**Графики — SVG своими руками** (`TrendChart.tsx`). *Почему:* нужен один тип
графика (линия + полоса нормы + подсказка); без лишней библиотеки.

**Иконки — встроенный SVG и сгенерированная иконка приложения.** Иконку рисует
скрипт на стандартном Python, `tauri icon` нарезает все размеры.

**Связь интерфейса и ядра — команды Tauri (IPC).** Интерфейс вызывает
`invoke("save_checkin", …)`, Rust выполняет внутри процесса. *Почему:* без HTTP
и без localhost в установленной программе; каждая команда заново проверяет
данные и роль пользователя.

**Локальная база — SQLite** (встроена через SQLx). Один файл в папке данных
пользователя. *Почему:* полностью работает без связи, ничего не нужно
устанавливать, надёжные транзакции (режим WAL). Триггеры запрещают изменять
медицинские записи.

**Доступ к базе — SQLx 0.8.** *Почему:* асинхронный (не блокирует программу
при ожидании), встроенные миграции (`migrations/*.sql` применяются при
запуске), одна библиотека для десктопа и сервера, поддержка PostgreSQL в
будущем. Запросы — обычный SQL с проверкой при выполнении, сборке не нужна
живая база. Выбрана проверенная линия 0.8, а не совсем новая 0.9.

**База сервера — SQLite для беты.** *Почему:* один файл, демо запускается одной
командой. *Компромисс:* одновременно пишет только один процесс; для реальной
многопользовательской работы планируется PostgreSQL (SQL переносимый).

**Серверный фреймворк — Axum 0.8 + Tokio.** HTTP API для синхронизации и
чтения данных врачами. *Почему:* основной веб-фреймворк Rust от команды Tokio,
небольшой и легко тестируется (тесты гоняют запросы через роутер в памяти с `tower`).

**HTTP-клиент — reqwest 0.12 с rustls.** Синхронизация десктоп → сервер.
*Почему:* стандартный клиент Rust; rustls — TLS на Rust без OpenSSL, готов к HTTPS.

**Сериализация — serde + serde_json.** Структуры Rust ↔ JSON для команд,
синхронизации и базы знаний. *Почему:* стандарт, генерируется автоматически.

**Идентификаторы записей — UUID v7.** *Почему:* создаются на устройстве даже без
связи, уникальны без сервера и сортируются по времени создания.

**Отпечатки содержимого — SHA-256 (sha2).** *Почему:* при синхронизации
отличают дубликат (тот же id и отпечаток) от конфликта (тот же id, другой
отпечаток), не сравнивая записи целиком.

**Ошибки — thiserror.** *Почему:* понятные типы ошибок; интерфейс показывает
ясное сообщение, а не падает.

**База знаний ассистента — JSON + поиск по словам.** 14 проверенных записей,
встроенных при компиляции. *Почему:* работает офлайн и пересказывает только
проверенные источники; языковой модели нет — значит, нет выдуманного медицинского текста.

**Тестирование — `cargo test` (встроен в Rust) + тестовая среда Tokio.**
Модульные тесты, тесты базы в памяти, HTTP-тесты сервера и демо-сценарии
(всего 93). **Линтер — Clippy**; **проверка типов — `tsc`**.

**Упаковка — NSIS через сборщик Tauri.** Установщик для текущего пользователя
с ярлыками и деинсталлятором. *Почему:* не нужны права администратора, привычно
для Windows. В бете без цифровой подписи.

**Контроль версий — Git + GitHub (приватный репозиторий).**

## 9. Ограничения
Пороги, кроме пределов NASA, — допущения; нет пароля; токен хранится без
шифрования; синхронизация по HTTP на localhost и только в одну сторону;
ассистент понимает только английский; данные устройств симулированы;
установщик не подписан.
